# 疑似乱数・準乱数の設計

## 1. 疑似乱数（`Tuna.RandomSource`）

### 共通設計・スレッド安全性・再現性
- すべての `IRandomSource` 実装は非暗号学的（non-cryptographic）な疑似乱数生成器であり、インスタンスごとの `Lock` によりスレッドセーフです。
- 並列計算での再現性は、1 つのインスタンスを複数スレッドで共有するのではなく、タスクやチェーンごとに異なる `streamId` の独立インスタンスを作る設計を前提としています。
- `Fill(Span<T>)` はスカラー呼び出しを順に繰り返した場合と同一の列を生成します（`Fill(Span<byte>)` は 64-bit 出力をリトルエンディアン順に展開し、末尾の余剰バイトは破棄）。
- 有界整数生成には Lemire のほぼ除算なし棄却法（arXiv:1805.10941）を採用しています。
- `Shuffle` / `Permutation` は `RandomGenerator` 派生型に対してロックを 1 回だけ取得する高速経路を使いつつ、`NextInt32(i + 1)` を繰り返す場合とビット単位・乱数消費回数ともに完全に一致させます。
- 例外（Philox のストリーム枯渇など）が発生した場合、途中までの状態進行はロールバックしません。

### 共通の変換・消費仕様
| API | 仕様 |
| --- | --- |
| `NextDouble()` | 64-bit 出力の上位 53 bit を $2^{53}$ で割る（`[0, 1)`） |
| `NextDoubleOpen()` | 上記の 0 のみを棄却する（$[2^{-53}, 1 - 2^{-53}]$ の等間隔な値） |
| `NextSingle()` | 32-bit 出力の上位 24 bit を $2^{24}$ で割る（`[0, 1)`） |
| 範囲付き整数 | 乗算と棄却による偏りのない写像（Lemire 法）。上下限が等しい・結果が 1 通りの場合は乱数を消費しない |
| 符号付き上限が 0 / 符号なし上限が 0 | 符号付きは 0 を返し乱数を消費しない。符号なしは `ArgumentOutOfRangeException` |
| 長さ 0 の `Fill` / 不正な引数 | 乱数を消費しない |

### `Pcg64DxsmRandom`
- PCG CM DXSM 128/64（乗数 $M = \text{0xDA942042E4DD58B5}$、周期 $2^{128}$）を実装しています。状態更新は $s \leftarrow M s + c \pmod{2^{128}}$ で、出力は**更新前**の状態 $(h, l)$ から $t = (h \oplus (h \gg 32)) \cdot M$、$\text{output} = (t \oplus (t \gg 48)) \cdot (l \mid 1) \pmod{2^{64}}$ として計算します。
- **シード初期化**: UTF-8 文字列 `"Tuna.PCG64DXSM.v1"`、リトルエンディアン 8 バイトの `seed`・`streamId` を連結して SHA-256 を計算し、前半 16 バイトを $u$、後半 16 バイトを $v$（リトルエンディアン）として $c = v \mid 1$、$s = (u + c) M + c \pmod{2^{128}}$ とします。ライブラリ独自のシード導出であるため、同じ数値シードでも NumPy の `PCG64DXSM` とは異なる列になりますが、`Pcg64DxsmState` からの復元では生の状態・増分を NumPy 等と照合できます。
- **32-bit 出力と `Advance`**: 隠れた半語キャッシュを持たず、32-bit 要求でも 64-bit ステップを 1 回消費して上位 32 bit を返します。これにより `Pcg64DxsmState` を最小限に保ち、`Advance(UInt128)`（$\bmod 2^{128}$ での $O(\log n)$ アフィン二乗法、最大 128 反復）が 64-bit 出力ステップ数と厳密に 1 対 1 対応します。

### `Philox4x32Random`
- 10 ラウンドの Philox4x32（Salmon et al., SC11 2011）を実装しています（64-bit 鍵 = `seed` の下位・上位 32 bit、128-bit カウンタ = `blockIndex`・`streamId` の各下位・上位 32 bit、32-bit 乗数 `0xD2511F53` / `0xCD9E8D57`、ラウンド鍵増分 `0x9E3779B9` / `0xBB67AE85`）。
- 出力は `Word0` から順に消費し、`NextUInt64()` は連続 2 語を用いて先取得語を下位 32 bit にします。各ストリームは $2^{64}$ ブロック（1 ブロック = 4 語の `uint`）を生成し、終端を超えると `InvalidOperationException` をスローします（残り 1 語の状態で 64-bit 読み出しに失敗した場合は最後の 1 語を消費しません）。
- 一括生成では AVX2 の `vpmuludq` を用いて連続 4 ブロックを並列計算し、`FillPairs` では語数オーバーフローを防ぐため `MaxPairs = 1 << 28` 単位に分割して処理します。

### `BoundedCompositionSampler`
- 制約付き整数分割 $\{x \in \mathbb{Z}^n : l_i \le x_i \le u_i,\; \sum x_i = s\}$ を、後ろ向き DP の数え上げと前向き条件付きサンプリングで生成します。
- 下限シフト $y_i = x_i - l_i \in [0, c_i]$ と補数反転によりテーブル幅を $m' = \min(m, \sum c_i - m)$ に抑え、構築 $O(n \cdot m')$・サンプリング $O(\sum \min(c_i, m'))$ で動作します。
- DP の各行は 2 の冪（`Math.ILogB` / `Math.ScaleB`）で $[1, 2)$ にスケーリングしてオーバーフローを防ぎ、スライディングウィンドウ和には減算を伴わない van Herk–Gil–Werman 法＋Neumaier 補償加算を用いて桁落ちを防いでいます。
- 1 サンプルあたりの乱数消費は常に `NextDouble()` を $n - 1$ 回に固定しています（選択肢が 1 通りの成分であっても固定）。なお DP 値と `NextDouble()` が倍精度（解像度 $2^{-53}$）であるため、確率が $2^{-53}$ 付近以下の極めて稀な構成では丸めによる微小な偏りや脱落が生じ得ます。

## 2. 準乱数（`Tuna.QuasiRandom.SobolSequence`）

- **レイアウトと並列決定性**: `IPointSequence` は `Dimension × Count`（1 列 = 1 点）の列優先行列に点を書き込みます。範囲を分割して並列生成しても、一括生成とビット単位で一致します。
- **Gray code 生成**: 64-bit Gray code（$g = i \oplus (i \gg 1)$、Sobol' 1967 / Antonov & Saleev 1979）により、最大 $2^{64}$ 点・最大 1,111 次元を生成します。方向数は `directions[k * Dimension + j]`（左詰め `ulong`）の配置にしており、1 ステップ進行を全次元一括の `Vector<ulong>` XOR で処理します。
- **半 ULP シフト（0 と 1 を返さない座標）**: 上位 52 bit を $k$ として $(k + \tfrac{1}{2}) \cdot 2^{-52} \in [2^{-53}, 1 - 2^{-53}]$ を返します。非スクランブル時の第 0 点を含め厳密に $(0, 1)$ に収まるため、`XMath.Special.InverseNormalCdf` などの逆関数へそのまま渡せます。
- **スクランブル（RQMC）**: コンストラクタに `IRandomSource` を渡すと、次元ごとに `NextUInt64()` を 64 個消費し、先頭 63 個からランダムな単位下三角行列を構築して各次元の方向数に左から掛け（Matoušek 1998）、最後の 1 個をデジタルシフトの 64-bit XOR マスクに使います。どちらも正則変換であるため $(t, m, s)$-net の $t$ 値を保ちつつ、独立インスタンスの標本分散から不偏な誤差推定を行えます。点数は先頭から $2^m$ 個を使うことを前提としています（Owen 2020）。
- **クリーンルーム生成の方向数テーブル**: `SobolDirectionNumbers.Data.cs` の 1,111 次元テーブルは、Joe–Kuo (2008) や SciPy のデータに依存せず、リポジトリ内ツール（`tools/SobolDirectionNumbers`）によって GF(2) 原始多項式（次数 1〜13）と 2 次元射影コスト $\sum_{i<j}\sum_{m=1}^{20}(4^{t_m(i,j)} - 1)$ の最小化（ビームサーチ＋座標降下法、次数 6 以下は厳密分枝限定）で独自生成したものです。
- **不変性とスレッド安全性**: `SobolSequence` は構築後に不変であり、全メソッドがスレッドセーフです。
