# 線形代数・SIMD・並列化の設計

## 1. 決定的な SIMD 要素演算カーネル

連続メモリ上の `float` / `double` / `Complex` 要素演算（`src/Tuna/LinearAlgebra/Dense/`）は、**スカラー経路・ストライド付きビュー・SIMD 幅（Vector128 / 256 / 512）によらず、同一入力に対してビット単位で一致する**ことを設計目標としています。

### 正確な丸めが一意に決まる演算（`DenseElementwise.Exact.cs` / `.Complex.cs` / `.Magnitude.cs`）
- 四則演算・平方根・符号操作・比較選択など IEEE 754 で結果が一意に決まる演算を SIMD 化しています。
- 2 つ以上の入力が NaN の場合にどの NaN ペイロードが残るか、およびシグナリング NaN の静穏化は、IEEE 754 および JIT/ISA 依存のため保証対象外としています。
- `Max` / `Min` は .NET の `Vector*.Max/Min` が `Math.Max/Min` と同じ規則（NaN 伝播、`+0 > -0`）を持つためそのまま使用し、`Clamp` は比較と選択で記述して NaN 挙動を一致させています。
- `Hypot`（および `Complex.Magnitude`）は .NET の `Vector*.Hypot` がハードウェア SIMD 化されないため、`double` は `double.Hypot` と演算順序を合わせた自前 SIMD 実装、`float` は `double` へ拡幅して二乗和・平方根を計算してから丸める SIMD 実装（無限大を NaN より優先）を採用し、スカラー片側・ブロードキャスト経路ともビット単位で一致させています。

### 指数・対数・合成関数（`DenseElementwise.Transcendental.cs` / `.Composite.cs`）
- .NET 標準の `Vector*.Exp/Log` は誤差が大きいため使用せず、glibc や ARM Optimized Routines と同等の高精度実装を自前で用意しています。
  - **指数関数**: Tang の表引き法（Tang 1989）
  - **対数関数**: 区間中心 $c$ を用いた $\ln x = k \ln 2 + \ln c + \ln(z/c)$ の表引き法
- 各レーンはスカラー版と同一の演算列（FMA を含む。FMA は IEEE 754 で一意に決まるためハードウェア非対応環境でもソフトウェア実装で一致）を実行します。
- 特殊入力は次の 2 段階で処理します。
  1. 値が確定するケース（$\pm\infty$、オーバーフロー、0 へのアンダーフロー、$\ln 0 = -\infty$、NaN）はベクトルマスクで選択する。
  2. 表引きが使えない有限域（指数の非正規化域 $-746 < x < -708$、オーバーフロー直前 $708 < x < 710$、対数の非正規化入力）はそのレーンだけ `Math.Exp` / `Math.Log` へフォールバックする。
- `float` の高精度版は `double` へ拡幅して同一の式を通し、最後に `float` へ丸めます。
- `Tanh` は原点付近（$|x| \le 0.75$）を [4/4] Padé 近似で評価して桁落ちを防ぎ、それ以外は飽和境界 $|x| \ge 20$ で $\pm 1$ へ収めつつ `ExpNormal` を再利用して除算を 1 回に集約しています。

### 近似 `float` カーネル（`DenseElementwise.Approximate.cs`）
- `float` のまま計算し、表引き（gather）を使わない多項式近似により、1 ベクトルあたりの処理要素数を 2 倍にします（`Tanh` では原点付近に Chebyshev 補間、それ以外に単精度指数近似を組み合わせています）。
- `ISingleLanes` 抽象化の上に 1 度だけ式を書き、スカラー端数と各 SIMD 幅で完全なビット一致を保ちます。途中のクランプは `MinNative`/`MaxNative` を使い、NaN 入力は最後に元のレーンを選択し直します。

## 2. 縮約とペアワイズ加算木（`DenseReductions.cs`）

- 連続領域の和は、ストライド版 `StridedKernels.PairwiseSum` と同じ**固定木構造**（64 要素のブロック内を `T.Zero` から順次加算し、ブロック和を二進木状に結合）で計算します。
- SIMD 化では、独立した $L$ 個のブロックから $L$ 要素ずつ読み出し、$L \times L$ のタイル転置を行うことでレーン $k$ にブロック $k$ の $i$ 番目の項を並べます。これにより、各ブロック内の加算順序がスカラー実装と一致し、ISA に依存しないビット一致を実現しています。
- 行ごとの和は、列優先メモリ配置で各行の要素が列内に連続して並ぶため、行をそのまま SIMD レーンに割り当てます。

## 3. JIT 最適化属性と AVX/SSE 遷移ペナルティ回避

Tiered JIT（段階的 JIT）の初回実行性能（起動直後）とウォームアップ後のピーク性能を両立させるため、ホットパスのメソッド属性を次のルールで使い分けています。

- **ループ本体のメソッド**（`MapLine`, `ZipLines`, 選択アルゴリズムの `Select` 等）: `AggressiveOptimization` を付け、初回から最適化コードを生成する。
- **ループ内から必ず展開したい小関数**（`ILanes` 実装、演算子ラッパーの `Invoke`、各幅のベクトル版 `Exp`/`Log`）: `AggressiveInlining` を付ける（`AggressiveOptimization` メソッドは PGO による再最適化が行われないため、展開を明示しないとウォームアップ後に遅くなる）。
- **ループ外から呼ばれる大きいスカラー式**（スカラー版 `Exp`/`Log`, `Hypot` 等）: `AggressiveOptimization` のみを付ける。
- **ディスパッチ専用メソッド**（`TryMapLines` 等）: 属性を付けず、ウォームアップ後のインライン連鎖を阻害しないようにする。
- **1 本の連続区間 vs 複数区間**: 呼び出しを含むカーネルを区間ループの中に置くと 1 区間でも添字とポインタがスタックへスピルされるため、1 区間用と複数区間用を別メソッドに分けている。
- **ReadyToRun (SSE) と AVX 混在の回避**: AVX レジスタの上位ビットを使った状態のまま ReadyToRun で事前コンパイルされた SSE スカラー関数を呼ぶと、SSE/AVX 遷移ペナルティで数十倍低下することがあります。そのため、スカラー関数を呼ぶループはベクトル命令を含むメソッドから分離しています。

## 4. BLAS・複素 GEMM・順序統計量

### 複素 GEMM の 4M 法（`GemmComplex.cs`）
- 複素行列積 $C \leftarrow \mathrm{op}(A)\,\mathrm{op}(B)$ は、実部と虚部を並べた実行列積 $[ \mathrm{Re}\,C \mid \mathrm{Im}\,C ] = [ \mathrm{Re}\,A \mid \mathrm{Im}\,A ] \begin{bmatrix} \mathrm{Re}\,B & \mathrm{Im}\,B \\ -\mathrm{Im}\,B & \mathrm{Re}\,B \end{bmatrix}$（4M 法）として倍精度 `Gemm` に委譲しています。
- 3M 法と異なり打ち消しによる精度劣化がなく、誤差は直接の複素積和と同水準になります。
- 作業配列を抑えるため $C$ の列方向と内積方向を $(m, n, k)$ のみで決まる固定サイズにブロック分割しており、スレッド数に依存せず結果が一致します。
- 実部の 2 項 $\sum \mathrm{Re}\,a\,\mathrm{Re}\,b$ と $\sum (-\mathrm{Im}\,a\,\mathrm{Im}\,b)$ を分離加算する関係上、稀に中間オーバーフローで $\infty$ / NaN が生じた列は、直接の複素積和経路で再計算します。

### 中央値・分位点の選択アルゴリズム（`StridedKernels.OrderStatistics.cs`）
- ソート全体（$O(n \log n)$）を避け、Floyd & Rivest の SELECT アルゴリズム（平均比較回数 約 $1.5n$、$O(n)$）で目的順位のみを求めます。
- 浮動小数点（`double`, `float`, `Half`）は全順序を保つ整数キー（`BitsKey`）へ変換して比較します。
- 標本抽出は山形配列などの偏った入力で劣化しないよう固定シードの疑似乱数で範囲全体から選び、比較予算を超えた場合はソートへ切り替えて最悪計算量を $O(n \log n)$ に抑えます。

## 5. 行列分解・二段階縮約・並列化

### 対称固有値分解のアルゴリズム選択
- 三重対角化後、固有ベクトルを求める $n > 25$ では Cuppen の分割統治法（LAPACK `dsyevd` / `dstedc` 相当、Gu–Eisenstat の直交性回復を含む）、それ以外は QL 法を使用します。
- 固有値のみを求める大規模行列（既定 $n \ge 2048$、`LinearAlgebraSettings.TwoStageReduction`）では、二段階三重対角化（LAPACK `dsytrd_2stage` 相当）を使用します。
  - 第 1 段（密行列 → 帯幅 $b$ の帯行列）は計算がすべてレベル 3 BLAS（行列積）となり、メモリ帯域律速を回避します。
  - 第 2 段（帯行列 → 三重対角）はバルジ追跡をキャッシュに収まる $2b \times b$ ブロック内で行います（$O(n^2 b)$）。固有ベクトルが必要な場合は逆変換コストが約 $2n^3$ 増えるため、既定では固有値のみ計算時に採用しています。

### 特異値分解（SVD）の二段階二重対角化と分割統治法
- **二段階上二重対角化（`TwoStageBidiagonal.cs`、`dgebrd_2stage` 相当）**: 一段階縮約では 1 列ごとに残余行列を 2 回読む行列ベクトル積がメモリ帯域に律速されるため、第 1 段（`dgebrd_ge2gb`）で QR / LQ ブロック分解によりすべて行列積で帯幅 $b$ の上三角帯行列へ縮約し、第 2 段で左右からのバルジ追跡により二重対角行列へ仕上げます。
- **並列パネル分解（`BidiagonalPanel.cs`、`dlabrd` 相当）**: 反射ごとの行列ベクトル積 $A^\top u, A v$ と補正項を同一列担当スレッド（owner-computes）に集約し、キャッシュ局所性を保つとともに `Rent`/`Return` でバッファを再利用します。
- **分割統治法（`BidiagonalDivideConquer.cs`、`dbdsdc` 相当）**: $n > 25$ では中央の行を取り除いて再帰分解し、永年方程式と Gu–Eisenstat 法による直交性回復で統合します（$n \le 25$ の葉は `BidiagonalSvd` の QR 法）。

### 一般固有値分解のバランシングと先読み並列化
- `HessenbergReduction` のバランシング（`dgebal` 相当）では、列優先の行ノルム計算でストライド読み出しを繰り返さないよう転置コピー $A^\top$ を保持し、2 の冪のスケーリング倍率で連続読み出しのまま収束させ、最後に 1 回だけ $A$ をスケーリングします。
- `HessenbergQr` では LAPACK `dlaqr0`/`dlaqr3`/`dlaqr5` 相当の積極的早期収縮とマルチシフト掃引を用い、並列実行時は次の窓に入る列への更新だけを先行させ、残りの列・行・$Z$ の更新を次窓のバルジ追跡と並行実行する先読み（lookahead）を行います。

### Owner-Computes 列分担と `Recompute` のゼロ割り当て（`ColumnTeam.cs`）
- パネル縮約では各スレッドが同じ列区間を継続的に担当（owner-computes）することで、各コアの L2 キャッシュに列ブロックを残します。
- 部分和の区間数と境界はスレッド数ではなく行列次数だけで決め（600 行以上では 2・3・4・6 並列で偏らないよう 12 の倍数）、並列数に依存しない再現性を保っています。
- `ColumnTeam` はスレッドごとに `Rent`/`Return` で使い回し、`Recompute` 呼び出し時のヒープ割り当てを防いでいます。
- `BatchCholeskyDecomposition` は、単体行列が小さければ行列単位で並列化し、大きければ行列を順次処理して各行列の内部を並列化します。どちらの経路でも各スライスの結果は単体 `CholeskyDecomposition` とビット単位で一致します。
